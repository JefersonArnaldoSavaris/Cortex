# Trading Opportunities

`Trading Opportunities` is a short-term analysis module for preliminary Day Trade
and Swing Trade opportunities. It generates structured technical signals for
education, simulation and human review. It does not place real orders and must
not be treated as financial advice.

## Risk Notice

Signals are technical-analysis outputs only. They can be wrong, stale or
incomplete, especially during high volatility, low liquidity, news events,
spread widening, data-provider failures or broker execution differences. Always
validate any idea manually before making a trading decision.

## CLI Usage

```bash
cortex opportunities \
  --symbol SPY \
  --strategy-type daytrade \
  --timeframe M15 \
  --risk-profile moderado \
  --capital 10000 \
  --max-risk-per-trade 0.01 \
  --max-signals 1 \
  --provider mock
```

The command prints JSON with fields such as:

- `symbol`
- `strategy_type`
- `timeframe`
- `direction`: `BUY`, `SELL`, `WAIT` or `AVOID`
- `confidence_score`
- `setup_name`
- `entry_price`
- `stop_loss`
- `take_profit`
- `risk_reward_ratio`
- `position_size`
- `max_loss`
- `technical_reasons`
- `risk_reasons`
- `invalidation_criteria`
- `warnings`
- `generated_at`

## Python Usage

```python
from cortex.trading_opportunities import OpportunityRequest, TradingOpportunityAgent

request = OpportunityRequest(
    symbol="SPY",
    strategy_type="daytrade",
    timeframe="M15",
    risk_profile="moderado",
    capital=10_000,
    max_risk_per_trade=0.01,
    max_signals=1,
    provider="mock",
)

result = TradingOpportunityAgent().analyze(request)
print(result.model_dump(mode="json"))
```

## API Usage

Start the API:

```bash
cd Cortex
source .venv-cortex/bin/activate  # or your project virtualenv
uvicorn apps.api.cortex_api.main:app --reload --port 8000
```

Request:

```bash
curl -X POST http://localhost:8000/opportunities/analyze \
  -H "Content-Type: application/json" \
  -d '{
    "symbol": "SPY",
    "strategy_type": "daytrade",
    "timeframe": "M15",
    "risk_profile": "moderado",
    "capital": 10000,
    "max_risk_per_trade": 0.01,
    "max_signals": 1,
    "provider": "mock",
    "limit": 160
  }'
```

The response is the same structured JSON generated by
`TradingOpportunityAgent`, including `signals`, `technical_reasons`,
`risk_reasons`, `invalidation_criteria` and `warnings`.

## Web Usage

Start the frontend:

```bash
cd Cortex/apps/web
npm install
npm run dev
```

Open `http://localhost:3000` and select the `Oportunidades` tab. Fill in the
form and click `Analisar oportunidade`. The result area shows direction,
confidence score, setup, entry, stop loss, take profit, risk/reward, theoretical
position size, maximum estimated loss, invalidation criteria and warnings. When
available, entry/stop/take-profit levels are also shown visually on the market
chart.

## Providers

- `mock`: deterministic synthetic OHLCV data for development and tests.
- `yfinance`: read-only Yahoo Finance OHLCV when available for the requested
  symbol and timeframe.
- `mt5`: safe stub only. It exposes the future method shape but raises
  `NotImplementedError`.

## Audit Log

By default, each analysis appends a JSON audit entry to:

```text
~/.cortex/memory/trading_opportunities.md
```

Override it with `CORTEX_OPPORTUNITY_LOG_PATH`. Use `--no-audit-log` in the CLI
to disable logging for that run.

## MT5 Future Plan

The current MT5 class intentionally blocks live trading. A future commercial
integration can implement:

- `connect()`
- `get_account_info()`
- `get_symbols()`
- `get_ohlcv(symbol, timeframe, limit)`
- `get_current_price(symbol)`
- broker-specific risk and lot-size normalization

`place_order()` must remain gated behind a separate execution layer, explicit
operator consent, credential isolation and audit controls. In this stage,
`ENABLE_LIVE_TRADING=false` is the default and even setting it to true does not
enable live order execution.
